# Chunk NBT format and region IO: Pumpkin vs decompiled vanilla

## Verdict

Chunk NBT field coverage and the Anvil region layout are largely a MATCH: Pumpkin reads/writes DataVersion, Status, sections, Heightmaps, block_entities, block_ticks/fluid_ticks, isLightOn, InhabitedTime, LastUpdate and x/y/zPos, and mirrors the 2-sector header, location+timestamp tables, sector bitmap, `.mcc` external chunks (256-sector threshold, 0x80 flag) and gzip/zlib/lz4/none compression. The structural MISSING gaps are the entire DataFixer/old-DataVersion migration path and any behavioural use of `blending_data`/`below_zero_retrogen`/`UpgradeData`; differences otherwise are defensive-check and failure-recovery details. Total gaps: 10 (5 MISSING: the DataFixer migration path, its fields and the newer-version guard; 5 DIFFERS).

## Verified matches

- **Region header/layout**: 2-sector (8192-byte) header, 1024 location entries of `(offset<<8)|sectorCount`, 1024 timestamps; sectors start at 2 and header sectors are marked used — Pumpkin `anvil.rs:27-31,306,659,669-697,602-610` vs vanilla `RegionFile.java:28-31,436-447,853-856`.
- **Sector allocation and external chunks**: used-sector bitmap, allocation/free on write, best-fit vs first-fit is an implementation detail only; oversized chunks (256+ sectors) go to `c.<x>.<z>.mcc` with a 1-sector stub whose compression byte carries the 0x80 external flag — Pumpkin `anvil.rs:302-304,376-405,470-498,561-573` vs `RegionFile.java:34,801-835,837-851`.
- **Compression codecs**: gzip=1, zlib=2, none=3, lz4=4, custom=127 rejected on both sides; Pumpkin also sniffs old uncompressed records by leading NBT tag byte — `anvil.rs:69-74,154-181,278-297` vs `RegionFileVersion.java:26-45`.
- **Crash-safe write ordering**: data written into free sectors, then header, then old sectors freed; Pumpkin additionally keeps staged chunks on failed flush — `anvil.rs:424-426,457-540` vs `RegionFile.java:792-822`.
- **NBT fields written/read**: DataVersion, xPos/yPos/zPos, LastUpdate, InhabitedTime, Status, Heightmaps, sections (Y/block_states/data/palette/biomes/BlockLight/SkyLight), block_ticks, fluid_ticks, block_entities, isLightOn — Pumpkin `format/mod.rs:762-923` (write) and `:440-706` (read) vs `SerializableChunkData.java:538-630` (write) and `:140-192` (read).
- **Heightmaps**: three computed keys WORLD_SURFACE/MOTION_BLOCKING/MOTION_BLOCKING_NO_LEAVES plus uncomputed keys (e.g. OCEAN_FLOOR) preserved across load/save — `format/mod.rs:579-623,782-795` and test `:2145-2176` vs `SerializableChunkData.java:164-169,607-609`.
- **Unmodelled tags survive a load/save cycle**: `structures` and `PostProcessing` (and `carving_mask`) are stored in `preserved_tags` and re-emitted before modelled tags overwrite them — `format/mod.rs:43-89,746-760` and test `:2105-2143` vs `SerializableChunkData.java:606,610` (both fields are real vanilla chunk tags).
- **ChunkStatus set matches** exactly (empty, structure_starts, structure_references, biomes, terrain, features, initialize_light, light, spawn, full); Pumpkin additionally folds legacy `noise`/`surface`/`carvers` into Terrain — `pumpkin-data/src/generated/chunk_status.rs:4-38`, `format/mod.rs:661-675,768-779` vs `world/level/chunk/status/ChunkStatus.java:21-30`.
- **Scheduled ticks** use the same `x,y,z,t,p,i` compound layout for both block_ticks and fluid_ticks — `format/mod.rs:624-644,887-911` vs `SerializableChunkData.java:96-97,170-172,627-630`.
- **Entity chunks use a separate region folder** (`entities/`), mirroring vanilla's entity region storage, and go through the same DataFixer on load in vanilla — Pumpkin `format/mod.rs:1464-1467` vs `world/level/chunk/storage/EntityStorage.java:55-90`.

## Note on the task's "Lights" field

No root-level `Lights` NBT tag exists in either code base (grep across `.vendor/vanilla-decompiled/net/minecraft` and `crates/pumpkin-world/src/chunk` returned nothing). Light is stored per-section as `BlockLight`/`SkyLight` byte arrays, which both implementations read and write (`format/mod.rs:488-522,857-881`; `SerializableChunkData.java:107-108,564-570`). Pumpkin's sky-light "uniform section" omission/restore logic (`format/mod.rs:293-332,867-881`) is a Pumpkin-specific optimisation with no vanilla counterpart, but round-trips the same light values.
