# Paletted containers, sections and heightmaps: Pumpkin vs decompiled vanilla

## Verdict

Palette bit packing, resize thresholds and network/disk encodings largely MATCH vanilla: 0-bit single, 4-bit indirect blocks to 8 bits, direct global above that; 1-3-bit indirect biomes; 9-bit/37-long heightmaps at the shipped world heights.
Real gaps are mostly structural: only 3 of 6 vanilla heightmap types are computed, the heightmap bit width is hardcoded instead of derived from world height, section counts are derived rather than maintained, and several predicates are hard-coded tag proxies.
Total gaps: 9 (1 MISSING, 8 DIFFERS) out of 17 audited behaviours.

## Verified matches

- **Packing order and bit layout**: `flat_index = (y*DIM+z)*DIM+x` equals vanilla `getIndex`; both bit storages keep values inside a single word (`64/bits` values per long, ceil word count). Pumpkin `palette.rs:36-38`, `bit_storage.rs:64-85,98-140` vs vanilla `Strategy.java:69-71`, `SimpleBitStorage.java:259-269,313-327`.
- **Resize thresholds**: single→2nd value → 4-bit linear; linear full at 16 → 5-bit hash; hash full at 2^bits → +1 bit; >256 distinct → global/dense. Pumpkin `palette.rs:123-142,201-224,449-470` vs `Strategy.java:37-45`, `LinearPalette.java:40-55`, `HashMapPalette.java:34-50`, `PalettedContainer.java:168-187`.
- **Block network encoding**: 0 bits + Single; 4-8 bit indirect for 2-256 entries; direct with `ceil_log2(state_count)` bits above 256 (Pumpkin `MIN/MAP_BITS=4/8`, `block_network_max_bits`) — matches `Configuration.Simple`/`Global` write semantics. Pumpkin `palette.rs:785-835,1284-1295` vs `PalettedContainer.java:525-535`, `GlobalPalette.java:35-45`.
- **Biome network encoding**: 0/1-3 bit indirect up to 8 entries, direct 7 bits above (67 biomes → ceil_log2 = 7). Pumpkin `palette.rs:543-591,1298-1302` vs `Strategy.java:50-63`.
- **Disk encoding**: palette size → bits (blocks min 4, biomes min 0), single value emits no `data` array, words reused when width matches; vanilla's `bitsPerEntry = -1` makes its declared-bits check a no-op for NBT. Pumpkin `palette.rs:282-342,345-440,677-689,1011-1022` vs `PalettedContainer.java:288-327,352-423`, `PalettedContainerRO.java:40-45`.
- **Heightmap update rules**: opaque at/above first available raises the column; non-opaque at first-available-1 scans down for an opaque block, else bottoms out at min_y; updates below `first_available-2` are ignored. Pumpkin `mod.rs:286-345` vs `Heightmap.java:93-120`.
- **Stored height encoding**: Pumpkin stores `y - min_y + 1` for a block at `y`; vanilla stores `(y + 1) - min_y` — identical bits; empty column decodes to `min_y - 1` on both. Pumpkin `mod.rs:246-283,310-343` vs `Heightmap.java:122-141`.
- **Section/accessor scan**: top-down search for the highest section with `!has_only_air`, and `get_top_y` descending scan, mirror `getHighestFilledSectionIndex` / `getHeight`. Pumpkin `mod.rs:696-710,1042-1053` vs `ChunkAccess.java:483-500,543-555`.
- **Ticking fluid predicate**: Pumpkin's LAVA-only check equals vanilla's `FluidState.isRandomlyTicking()` (only `LavaFluid` overrides the `false` base). Pumpkin `palette.rs:42-44` vs `Fluid.java:79-81`, `LavaFluid.java:243`, `FluidState.java:127-128`.
