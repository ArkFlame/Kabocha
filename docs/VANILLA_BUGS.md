# Vanilla quirks we keep on purpose

Registry of vanilla behaviour that looks like a bug or an accident, but that we reproduce because datapacks, clients and other servers see it. A worker must not "fix" an entry here without a file upstream issue first. Every row was verified in the listed file line on master; if the line moves, fix the row, not the behaviour.

Source threads: `docs/TODO_2.md` section 6 (Discord lessons), plus a grep of `crates/pumpkin-core/src` and `crates/pumpkin-world/src` for `mirrors vanilla` / `vanilla also` / `vanilla does`.

| Area | Behaviour we keep | Vanilla source | Ours | Why kept |
|---|---|---|---|---|
| Commands, number storage | `execute store ... short` and `... byte` narrow `double` through `int`, so out-of-range values wrap instead of saturating (a scaled 40000 written as `short` becomes negative). | `ExecuteCommand.wrapStores` | `crates/pumpkin-core/src/command/commands/execute.rs:765-769` | Datapacks depend on the stored value reading back identically; saturating would silently change scores. |
| Commands, `if data` | A missing NBT path counts as zero matches and the branch fails; it is not a command error. | `ExecuteCommand.checkMatchingData` | `crates/pumpkin-core/src/command/commands/execute.rs:1254-1255` | Command blocks and datapacks branch on "no match" all the time; an error aborts the whole function. |
| Commands, `store` write | Any syntax error raised while writing the stored value is swallowed. | `ExecuteCommand` store result callable | `crates/pumpkin-core/src/command/commands/execute.rs:785-789` | Vanilla behaviour is "write best effort, never abort"; returning the error changes function execution. |
| Map, rotation | The item-frame/map rotation is `(byte)` narrowed through `int`, so it wraps at the 8-bit boundary instead of clamping; the Nether spin hash is `int` arithmetic that wraps on multiply. | `MapItemSavedData.calculateRotation` | `crates/pumpkin-core/src/world/map.rs:91-107` | The client renders whatever byte the server sends; wrapping is what the client expects for large rotations. |
| Block entity, updates | Container contents are not part of the block entity update tag, so a client only sees them when a window opens. | `BlockEntity.getUpdateTag` | `crates/pumpkin-core/src/block/entities/mod.rs:142-148` | Sending contents in the update tag is a cheat vector and breaks vanilla chunk streaming order. |
| Net, auth | Offline-mode UUID is the name-based v3 UUID: MD5 over `"OfflinePlayer:" + name`. | `UUIDUtil.createOfflinePlayerUUID` | `crates/pumpkin-core/src/net/mod.rs:72-76` | Existing offline worlds, whitelists and plugins key on these UUIDs. Changing the derivation orphans player data. |
| Armor stand, damage | Break at 0.5 health or less (not 0); fire damage type ignites once for 5 s and then chips 0.15 per hit; "burning" type deals 4.0 only while health is above 0.5. | `ArmorStand#causeDamage`, `ArmorStand#hurtServer`, `IGNITES_ARMOR_STANDS` / `BURNS_ARMOR_STANDS` tags | `crates/pumpkin-core/src/entity/decoration/armor_stand.rs:282-293`, `:592-607` | Stands are damageable decorations; the odd thresholds are what makes them immune to fists but not to fire/explosions. |
| Armor stand, drops | `brokenByAnything` plays the break sound, iterates every equipment slot (main hand, head, chest, legs, feet, body, saddle, off hand) and drops each non-empty stack one block above the stand. | `ArmorStand#brokenByAnything` | `crates/pumpkin-core/src/entity/decoration/armor_stand.rs:230-262` | Item loss/duplication bugs here are player-visible; the slot list and the `up()` drop position are vanilla's. |
| Command block, redstone | Only a power edge mutates `powered`; a REDSTONE-mode rising edge schedules execution one tick later, while chain and automatic blocks never schedule from the edge. | `CommandBlock.setPoweredAndUpdate` | `crates/pumpkin-core/src/block/blocks/command.rs:110-132` | Contraptions and clocks rely on edge semantics; "fixing" it to level semantics double-fires commands. |
| Natural spawning, caps | A mob spawned this tick counts towards the global cap and the nearby players' local caps immediately, not from the next rebuilt spawn state. | `NaturalSpawner.SpawnState#afterSpawn` | `crates/pumpkin-core/src/world/natural_spawner.rs:532-544` | Otherwise a single tick can overshoot the mob cap by a whole batch. |
| Effects, random gate | A consume-effect chance applies on strict `random < probability`, so probability 0 never applies and probability 1 always does. | consume-effect gate in `LivingEntity` | `crates/pumpkin-core/src/entity/living.rs:5494-5497` | Off-by-one at the boundary is observable with `< 1.0` chances and with the exact same RNG stream. |
| Projectiles, NBT | Arrow `life` is written as an NBT short and `shake` as a byte, so both wrap past the 16/8-bit range instead of being clamped. | `AbstractArrow.addAdditionalSaveData` | `crates/pumpkin-core/src/entity/projectile/abstract_arrow.rs:82-86` | Save files and chunk dumps must byte-match vanilla; clamping would change the reloaded arrow's lifetime. |
| Worldgen, light | A chunk with no sky array above the highest stored section reads as fully lit (15), and nothing is stored below the world, so the Nether stays dark. | `SkyLightSectionStorage.getLightValue` | `crates/pumpkin-world/src/chunk/format/mod.rs:275-286` | Lighting is what clients predict; imported vanilla saves must load with identical light. |
| Worldgen, feature order | Feature placement order is fixed and ties between otherwise independent features are broken by the vanilla biome array order; flat worlds place decorations in vanilla step order. The generator must never sort or parallelise features by availability. | `FeatureSorter`, `FlatLevelGeneratorSettings` | `crates/pumpkin-world/src/generation/feature_order.rs:7`, `crates/pumpkin-world/src/generation/generator/flat.rs:14` | Decoration order decides tree placement and overlaps; reordering diverges from vanilla chunk output even with identical noise. |
| Worldgen, math rounding | `pow` (and `log10`) can differ by 1 ulp between the JVM's CPU math stubs and fdlibm on another CPU. Vanilla does not agree with itself, so we do not chase per-CPU bit-identity in the density functions. | JVM intrinsics vs fdlibm (`StrictMath`) | `crates/pumpkin-world/src/generation/noise/router/density_function/math.rs:211`, `:287`, `crates/pumpkin-world/src/biome/position_finder.rs:377` | One ulp only matters where a noise value lands exactly on a threshold. Get a differential harness with golden vectors before changing the algorithm. |

## Deliberate deviations (not a licence to "fix" neighbours)

These are places where we knowingly differ, recorded so nobody copies them as precedent:

- `ItemEntity` age is clamped to `i16::MAX` when written instead of wrapping (`crates/pumpkin-core/src/entity/item.rs:899-904`), and `Health`/`PickupDelay` are narrowed the same way. A vanilla save that wrote a negative age would load differently; we accept that until a save round-trip test proves otherwise.
