## Result

VERIFIED (no code change). Row 8 is a verify note ("S (verify)", "Behavioural effect is the client graph only"); this task removes the old "outside this unit" reason, so I checked it against decompiled vanilla directly.

Vanilla (.vendor/vanilla-decompiled): ServerDebugSubscribers.tick() rebuilds the subscriber list each tick from players' debugSubscriptions(), and RemoteSampleLogger.useSample() broadcasts one ClientboundDebugSamplePacket per tick, gated by MinecraftServer.isTickTimeLoggingEnabled() = hasAnySubscriberFor(DEDICATED_SERVER_TICK_TIME). hasRequiredPermissions() is isOp on dedicated. The 4-long sample follows TpsDebugDimensions order [FULL_TICK, TICK_SERVER_METHOD, SCHEDULED_TASKS, IDLE]; sample type is RemoteDebugSampleType.TICK_TIME (ordinal 0). fullTime = wall clock between tick ends; idle = max(0, fullTime - tickMethod - tasks).

Pumpkin (server/mod.rs:2006-2046 update_tick_times) already matches for the observable client-graph behavior:
- one CDebugSample per tick to each subscriber with permission >= 2 (hasRequiredPermissions parity); subscription handlers in net/java/play/debug_{sample_subscription,subscription_request}.rs gate on OP + TICK_TIME too.
- wire format matches: VarInt length + 4 i64s + VarInt type 0 (CDebugSample::write_packet_data, pumpkin-protocol/.../debug_sample.rs).
- sample [max(work,target), work, 0, idle] maps to vanilla's layout: max(work,target) == work + saturating_sub(target,work) == reconstructed FULL_TICK; work == TICK_SERVER_METHOD; idle == IDLE.
- gating is behaviorally equivalent: the recipient iterator is empty when nobody subscribes, so no packet is built/sent for non-subscribers, matching vanilla's isTickTimeLoggingEnabled() gate.

Only divergence: dimension [2] SCHEDULED_TASKS is hardcoded 0 because Pumpkin folds scheduled-function time into the overall tick work (tick_worlds runs inside server.tick()), so it cannot be separated without new instrumentation. Client-graph-only, not worth the churn. No seam for a pure unit test (method needs full Server state). No .rs file touched, so no rustfmt needed.

Related but out of this row's scope (send side): vanilla 1.21.4's serverbound subscription packet carries a SET of subscriptions with replace semantics (supports unsubscribe); Pumpkin's packet is a single sample_type VarInt with a set-only flag. That belongs to a protocol/subscription pass, not update_tick_times.
