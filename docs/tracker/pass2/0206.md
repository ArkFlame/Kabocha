`confirm_teleport.rs` / `await_teleport`.

`net/bedrock/play/player_action.rs`: the two non-duplicate dropped actions are now handled before
the `has_client_loaded` guard (needed because a dimension change clears that flag):
`HandledTeleport` and `ChangeDimensionAck` take the pending `awaiting_teleport`, clear
`is_changing_dimension` and set the client loaded. This is the same state transition the proximity
fallback in `player_auth_input.rs::await_teleport` applies, so a client that stops near but not on
the target no longer loops the 20-input resend. No protocol change needed: the ack arrives on the
`SPlayerAction` packet, unlike the still-open `await_teleport` row which assumed only the auth-input
transport. Guard stays a no-op when nothing is pending.

The remaining catch-all actions (`StartSneaking`/`StopSneaking`, `StartUsingItem`/`StopUsingItem`,
`StartJump`, `MissedSwing`) are intentionally left dropped: duplicate transports whose effects
already run every tick (sneak bits and embedded item interaction in `player_auth_input.rs`, swing
broadcast in `animate.rs`, riding-jump from the auth-input `StartJumping` flag). Adding them here
would double-apply side effects, as the source doc noted. Replaced the bare `// TODO` with a comment
explaining this. No pure unit-test seam (logic is Player-state mutation behind a mutex); no test
added.
