## Result

VERIFIED - the row's fix is already present in the code (concurrent/prior edit), so no source edits by me.
Vanilla `MeleeAttackGoal.tick` adds 15 to `ticksUntilNextPathRecalculation` when `moveTo` fails
(MeleeAttackGoal.java:115-117). Pumpkin now records `last_path_search_failed` in
`PathNavigation::update_path` (pathfinder/mod.rs:887) when the deferred search installs no usable path,
exposes `take_last_path_search_failed` through `PathNavigationTrait` (pathfinder/mod.rs:391, default false)
with all five navigators delegating, and clears it on each new `set_progress` (pathfinder/mod.rs:567).
`MeleeAttackGoal::tick` consumes the flag on the following tick and adds +15 (melee_attack.rs:269-277).
`get_tick_count` is identity for this goal (`should_run_every_tick` is true), so adding 15 after the
already-adjusted base matches vanilla's single `adjustedTickDelay`. No pure unit-test seam exists for
the one-line backoff (the flag lives in the navigator); test omitted per no-formula-mirror rule.
