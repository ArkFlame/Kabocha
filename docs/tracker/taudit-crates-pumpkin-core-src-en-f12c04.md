## Result
- `record_movement` merge (row 22, S): FIXED. Verified against decompiled `Entity.addMovementThisTick` (`Entity.java:1538-1547`): vanilla removes the two oldest and prepends `new Movement(first.from, second.to)` with no requested axis. Pumpkin's pop-front + in-place fold of the second record is equivalent. Extracted the merge into pure `merge_oldest_movement(&mut VecDeque<BoatMovement>)` and added `record_movement_merges_oldest_pair_at_cap`, which pins the list length, the folded `from`/`to`, and the cleared `requested`.
- `furthest_corner` sign (row 23, S verify): verified, NO CHANGE. Decompiled `BlockGetter.getFurthestCorner` (`BlockGetter.java:324-336`) uses `direction.x >= 0.0 ? 1 : -1`, so `0.0` maps to `+1`, identical to Pumpkin's `sign` closure at `block_effects.rs:247`. The traversal step sign (`traversal_steps`) matches `Mth.sign` (`0` for `0.0`) via `Vector3::sign` semantics.
- zero-movement fallback (row 24, S verify): verified, NO CHANGE. Decompiled `Entity.applyEffectsFromBlocks` (`Entity.java:1525-1529`) sweeps `new Movement(oldPosition(), position())` when no movement was recorded; Pumpkin uses `last_pos`, which equals `oldPosition()` because `update_last_pos()` runs at tick start (`entity/mod.rs:7046`), and the `9.9999994E-11F` threshold equals `(float)1e-5` squared, matching `BLOCK_INTERSECTION_EPSILON` squared.
- all-block `entityInside` (row 21, M): verified, LEFT OPEN. Decompiled `Entity.checkInsideBlocks` (`Entity.java:2037-2061`) calls `state.entityInside` for every visited non-air block whose inside shape meets the sweep, so Pumpkin's lily-pad-only filter at `block_effects.rs:85` is a real gap. One-line reason: a correct fix must dedupe against `Entity::tick_block_collisions` (`entity/mod.rs:3211-3283`, outside this unit) or damage blocks fire twice per tick, and the clean signature fix extends `OnEntityCollisionArgs` (`block/mod.rs:368`, outside this unit).
