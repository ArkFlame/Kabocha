## Result

FIXED. The test side was wrong: the fixture used `difficulty = peaceful` with a bare, unquoted string, which is invalid TOML syntax (string values must be quoted). Because `difficulty` is an unknown root field, that syntax error is not attached to a recoverable field and poisons the whole parse, unlike the intentional semantic invalid values (`"six"`, `"Invalid"`, `"yes"`) which are quoted and produce recoverable diagnostics. Quoting it to `difficulty = "peaceful"` makes the fixture valid TOML so the loader retains valid fields and the unchanged-source assertion holds. Config parsing has no decompiled-vanilla analogue; this follows the unit-doc rule that older pumpkin.toml files must keep loading.
